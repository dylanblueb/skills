# Make HTML

生成可独立阅读、分享的 HTML，不只是把 Markdown 套进网页。结构随内容决定；不强制分类、模板、主题或交互。短篇技能保持在本文件，无需加载附加参考。

## 生成流程

按以下顺序决定，不要为了套用模板而增加装饰或交互：

1. **判断交付物类型**：文章/文档、报告、概念解释、流程图、代码理解、设计系统、原型、编辑器、幻灯片，或其他。
2. **确认 HTML 是否有增益**：只有排版、可视化或交互能明显改善理解与使用时才生成 HTML；否则尊重用户指定的格式。
3. **选择页面结构**：内容类型决定 layout；可参考 `references/example-layout-catalog.md`，路由速查见 `references/routing.md`。简单内容优先单栏，不为短内容强行加入卡片、目录或导航。
4. **选择视觉主题**：优先继承用户、项目、产品或品牌风格；其次使用用户点名的主题，再按场景匹配保存主题，最后使用 `themes/fallback-theme.md`。主题决定视觉语言，不决定内容结构。
5. **决定交互复杂度**：只有存在真实状态变化、筛选、编辑、导航、复制、下载或反馈需求时才加入 JavaScript；静态内容必须在无 JS 时仍可阅读。
6. **生成自包含文件**：默认单个 `.html`，内联 CSS、必要 JS 与素材，不依赖 CDN、远程字体或构建工具。
7. **验证后交付**：检查结构、资源自包含、链接、响应式布局、可访问性与关键交互；浏览器可用时实测窄屏和交互。

核心原则：**内容决定布局，场景决定主题，状态决定交互，验证决定交付。**

## 交付约束

- 默认单个自包含 `.html`：CSS、必要的 JS 和素材内联，无 CDN、远程字体、构建或安装依赖。外部来源链接可以保留；用户明确需要联网功能时例外。
- 使用完整 HTML5：doctype、与正文语言匹配的 `lang`、UTF-8、viewport、有意义的 title。中文优先系统字体。
- Semantic HTML、responsive、accessible：语义化元素，带标签的原生控件，键盘可用、焦点可见、对比度清晰。窄屏不产生整页横向溢出；长字符串可换行，宽表格与代码局部滚动。
- 沿用用户或项目已有风格；没有则按内容设计，不绑定固定配色、字体或装饰。只有改善理解时才添加卡片、导航、图表或折叠。
- 仅添加有实际用途的交互。控件必须有效，视觉状态与适用的 ARIA 状态同步；编辑器应能复制或下载结果，破坏性操作可撤销或重置。静态内容不依赖 JS 才能阅读。
- 不编造数据、来源或验证结果。将独立理解所需的来源、单位和关键假设保留在页面内。将不可信内容当作文本处理，避免直接拼接进 HTML 或脚本。

## 验收与返回

交付前检查文档结构、资源自包含、链接与关键交互。浏览器可用时实测窄屏、布局及交互；不可用时做静态检查并说明未完成视觉或交互实测，不把静态检查称为浏览器验证。

能写文件时保存为简短、描述性的 `.html`，通过当前环境的文件交付能力返回；不能写文件时提供完整 HTML 代码块。简短说明产物及验证限制，不在聊天中重复整页内容。未经用户授权不上传或托管。
